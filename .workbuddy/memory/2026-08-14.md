### 定稿决策
1. 会话边界：按流程实例一整条，锚点 processNumber（与审计表一致）。
2. 权限：能打开页面即可看可发（不额外查参与人做鉴权）。
3. 回复模型：二级结构，parent_id 扁平存；根消息平铺，回复以「回复 @xxx」收在根消息下。落库额外存 root_id（所属根）+ reply_to_user/name（回给谁），避免递归回溯。
4. 内容形态：文本 + @提及（要做）+ 图片/附件仅预留字段（text 存 JSON url 数组，v1 不做上传）。
5. @提及对象：仅流程参与者（复用 `getBpmVerifyInfoVos(processNumber)` 拿 verifyUserName）。
6. @提及提醒：展示 + 发站内信（复用 `UserMsgUtils.insertUserMessage` / `InSiteSendAdaptor`，落 UserMessage 表，url 指向沟通面板）。
7. 刷新：打开面板时才主动查询，发送后本地追加，不做轮询/长连接。
8. 未读红点：不做（@提及由站内信自带红点承担）。
9. 新表 `t_bpm_process_comment`：id/process_number/parent_id/root_id/content/attachment(json)/mentions(json [{userId,userName}])/create_user/create_user_name/create_time/tenant_id/is_deleted。
10. 撤回：可撤回，软删除 is_deleted=1，前端展示「消息已撤回」。
11. 面板形式：drawer 聊天式（消息列表 + 底部输入框），与 auditDrawer 一致。
12. 入口范围：待办审批页 + 已办/发起查看 drawer 两处都显示。
13. FAB 改造：抽公共组件（如 ProcessFloatMenu.vue），封装「收起圆球 + hover 展开胶囊两项 + 两个 drawer」，approveForm/previewDrawer 都引用，消除重复。
