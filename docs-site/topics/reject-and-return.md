# 驳回与退回机制全解

> "这个申请不合规，打回让申请人修改。" — 中国式审批中最常见的操作。AntFlow 提供了 3 种退回策略 + 快捷评语 + 不/有异议/无法核实等细粒度驳回类型，覆盖从简单退回到复杂多级退回的全部场景。

## 审批操作按钮一览

当审批人打开待办任务时，会看到以下操作按钮（具体显示哪些由节点配置决定）：

![审批详情页](/images/topic-approve-detail.png)

| 按钮 | Code | 说明 |
|------|------|------|
| 同意 | 3 | 通过当前节点 |
| 不同意 | 4 | 直接终止流程 |
| 退回修改 | 18 | 退回到指定节点重新处理 |
| 加批 | 19 | 增加审批人（当前节点或未来节点） |
| 转办 | 21 | 将任务转给他人处理 |

## 退回的三种目标

点击「退回修改」后，弹出退回对话框：

![退回对话框](/images/topic-reject-dialog.png)

### 1. 退回上一节点

- 流程退回到**紧邻的上一个已审批节点**
- 该节点的审批人需要重新处理
- 最常用的退回方式

### 2. 退回发起人

- 直接退回到**流程发起人**
- 发起人可修改表单后重新提交
- 适用场景：材料不全、信息有误

### 3. 退回任意节点

- 可选择流程中的**任意历史节点**
- 支持跨级退回（跳过中间节点）
- 高级场景：退回到某个特定审批环节补充意见

## 快捷评语系统

退回对话框底部提供了快捷评语按钮，一键填充常见退回原因：

| 评语 | 使用场景 |
|------|---------|
| 不同意 | 明确拒绝，流程终止 |
| 有异议 | 表达保留意见但放行 |
| 不支持 | 资源/权限不支持该请求 |
| 无法核实 | 信息不足，无法判断 |
| 需要补充材料 | 要求申请人补件 |
| 不符合要求 | 违反规定/标准 |

> 💡 **管理员自定义**：快捷评语列表可在后端通过配置扩展，支持按租户/流程类型定制。

## 不同意 vs 退回修改的区别

这两个操作都会阻止流程继续向前，但有本质区别：

```
不同意 (DIS_AGREE, code=4)
┌──────────────────────────────┐
│  流程直接结束（终止态）       │
│  不可恢复                     │
│  状态: 已终止                 │
└──────────────────────────────┘

退回修改 (BACK_TO_MODIFY, code=18)
┌──────────────────────────────┐
│  流程回到指定节点             │
│  该节点人员可重新处理          │
│  状态: 审批中（退回中）        │
│  发起人可在"撤销/退回"中查看   │
└──────────────────────────────┘
```

| 维度 | 不同意 | 退回修改 |
|------|--------|----------|
| 流程状态 | 终止 | 继续运行（回退） |
| 发起人操作 | 可作废/发起新流程 | 可修改后重新提交 |
| 审批记录 | 记录为"不同意" | 记录为"退回至XX节点" |
| 可撤回 | 否 | 是（在到达前可撤回退回操作） |

## 退回后的用户路径

被退回的用户会在以下位置看到待处理任务：

1. **待办任务** → 出现新的待办（退回产生的任务）
2. **撤销/退回** → 专门的退回列表，展示所有被退回的流程

![撤销/退回列表](/images/topic-resubmit-list.png)

在撤销/退回页面，用户可以：
- 查看退回原因和评语
- 修改表单数据
- 重新提交（走一遍完整审批链）

## 审批记录中的退回轨迹

每次退回操作都会在审批记录 tab 中留下完整痕迹：

![审批记录](/images/topic-approve-record.png)

记录包含：
- 操作人、操作时间
- 操作类型（同意/不同意/退回）
- 退回目标节点
- 评语内容

## 后端实现要点

退回功能的核心实现位于 `GeneralRejectManagerImpl`：

1. **校验**：检查目标节点是否合法（不能退回到未来节点）
2. **状态更新**：将当前任务标记为已完成（退回完成）
3. **创建新任务**：在目标节点创建新的待办任务
4. **通知触发**：发送退回消息给目标节点处理人
5. **审计日志**：记录完整的退回操作链

退回任意节点 (`BACK_TO_ANY_NODE`, code=23) 是增强版退回，额外支持：
- 选择流程历史中的任一节点
- 跨级跳跃退回
- 退回到网关/条件分支内部节点

## 常见问题

**Q: 退回后原审批人的意见还在吗？**
A: 在的。所有历史审批意见都保留在审批记录中，包括被退回节点的原始审批结果。

**Q: 可以限制某些节点不允许被退回吗？**
A: 可以。在节点配置的「按钮权限设置」中，不勾选「退回」按钮即可隐藏该操作。

**Q: 退回后再撤回退回操作可以吗？**
A: 取决于流程是否已经从目标节点继续流转。如果目标节点尚未有人处理，发起人或有权人员可以撤回退回。
