# 条件分支与动态路由

> 不是所有流程都是一条直线。采购金额超过 10 万需要总监审批，请假 3 天以内主管即可放行，紧急工单走绿色通道……AntFlow 的条件分支引擎让同一套流程模板能根据表单数据自动选择不同的审批路径。

## 条件节点类型总览

在流程设计器中点击 `+` 按钮，可以看到丰富的条件类节点：

![添加节点菜单](/images/topic-designer-addnode.png)

| 节点类型 | 用途 | 特点 |
|---------|------|------|
| **条件分支** | 最常用的排他网关 | 按优先级匹配，只走一个分支 |
| **动态条件** | 运行时从外部获取条件 | 支持三方系统传入条件 |
| **条件并行** | 多个条件同时满足时并行执行 | 并行网关 + 条件组合 |
| **条件审批** | 带条件的审批节点 | 审批人根据条件动态确定 |
| **条件抄送** | 带条件的抄送节点 | 根据条件决定抄送对象 |

## 条件分支：最核心的路由机制

### 在画布上添加条件分支

1. 在两个节点之间点击 `+`
2. 选择「条件分支」
3. 画布上出现菱形条件网关：

![条件分支画布](/images/topic-condition-branch.png)

### 配置条件规则

点击「条件1」或「条件2」打开条件配置面板：

![条件配置面板](/images/topic-condition-config.png)

#### 条件组成要素

一个完整的条件由以下部分组成：

```
条件设置
├── 当审批单满足以下条件时进入此流程
├── 条件组 1（AND 关系：组内所有条件都满足）
│   ├── 条件 1: [字段] [比较符] [值]
│   ├── 条件 2: [字段] [比较符] [值]
│   └── ...
├── 添加条件组（OR 关系：任一条件组满足即通过）
├── 确 定
└── 取 消
```

#### 支持的比较符

| 符号 | 含义 | 示例 |
|------|------|------|
| 等于 | 精确匹配 | 金额 = 10000 |
| 不等于 | 排除特定值 | 类型 ≠ "个人" |
| 大于 / 大于等于 | 数值比较 | 天数 >= 3 |
| 小于 / 小于等于 | 数值比较 | 金额 < 50000 |
| 包含 | 字符串模糊匹配 | 标题包含"紧急" |
| 不包含 | 排除匹配 | 部门不包含"外包" |
| 为空 / 不为空 | 空值判断 | 附件不为空 |

### 优先级与默认分支

```
        ┌─────────┐
        │ 发起人   │
        └────┬────┘
             │
      ┌──────▼──────┐
      │ ◇ 条件分支    │
      └──┬───────┬──┘
         │       │
    ┌────▼──┐ ┌──▼────┐
    │条件1   │ │条件2   │
    │优先级1 │ │优先级2 │
    │金额>5万│ │(其他)  │
    └───┬───┘ └───┬───┘
        │         │
   ┌────▼──┐  ┌──▼────┐
   │ 总监   │  │ 经理   │
   │ 审批   │  │ 审批   │
   └───┬───┘  └───┬───┘
       │          │
       └─────┬────┘
             │
        ┌────▼────┐
        │ 流程结束  │
        └─────────┘
```

- **条件按优先级从高到低评估**：优先级 1 先匹配，命中后不再评估后续条件
- **最后一个条件通常设为"其他"**：作为兜底默认分支（无需配置具体规则）
- **所有条件都不满足**：流程停留在当前节点报错

### 实战示例：请假审批的条件路由

假设请假流程的表单包含字段：`请假天数`、`请假类型`

| 分支 | 条件 | 走向 |
|------|------|------|
| 条件 1 (优先级 1) | 请假天数 > 3 **且** 请假类型 = "年假" | HR 审批 → 总经理审批 |
| 条件 2 (优先级 2) | 请假天数 > 3 | 部门经理审批 → HR 备案 |
| 默认 (其他) | — | 直属主管审批即可 |

## 动态条件：运行时决策

当条件规则不是设计时能确定的（比如需要查外部系统、调用 API），使用**动态条件**节点：

- 条件由后端 `NodeTypeOutSideConditionsAdp` 处理
- 支持从三方系统实时拉取条件表达式
- 适用场景：风控系统实时返回审批路径、外部合规检查结果

## 条件并行：多路同时执行

当多个条件可能**同时满足**且需要**并行处理**时：

```
     发起人
        │
   ┌────▼────┐
   │ 条件并行  │
   └┬─────┬─┘
    │     │
  ┌─▼─┐ ┌─▼─┐
  │A  │ │B  │  ← 同时执行
  └─┬─┘ └─┬─┘
    │     │
   ┌─▼─────▼─┐
   │  汇聚     │  ← 等待所有分支完成
   └─────┬───┘
         │
      流程结束
```

典型场景：
- 采购申请同时需要财务审核 + 法务审核（互不依赖）
- 新员工入职同时需要 IT 开账号 + 行政发物资 + HR 入档

## 后端条件引擎

AntFlow 使用 **Drools 规则引擎** + Java SPI 双模式处理条件判断：

### Drools 模式（推荐）

```java
// 条件规则以 .drl 文件存储
rule "金额大于5万"
    when
        $form : BpmnBusinessDto(amount >= 50000)
    then
        // 走总监审批分支
end
```

### 自定义 Java 模式

实现 `ConditionFilterAdp` 接口：

```java
public class CustomConditionAdp implements ConditionFilterAdp {
    @Override
    public boolean evaluate(BpmnNodeConf nodeConf, Map<String, Object> formData) {
        Object amount = formData.get("amount");
        return amount != null && ((Number)amount).doubleValue() > 50000;
    }
}
```

## JSON 存储结构

条件配置存储在 `node_config_json.conditionsConf` 中：

```json
{
  "conditionsConf": {
    "conditionGroups": [
      {
        "priority": 1,
        "extJson": [
          [{"columnId": "amount", "optType": ">=", "zdy1": "50000"}]
        ]
      },
      {
        "priority": 2,
        "isDefault": true
      }
    ]
  }
}
```

## 常见问题

**Q: 条件可以嵌套吗？**
A: 支持 AND/OR 组合。同组内是 AND 关系，不同组之间是 OR 关系。

**Q: 条件中的表单字段从哪里来？**
A: 来自发起人提交的表单数据。DIY 表单的字段名由前端组件定义；LF 低代码表单的字段名在表单设计器中设定。

**Q: 条件匹配失败会怎样？**
A: 如果没有设置默认（"其他"）分支，且所有条件都不满足，流程会卡在条件节点并记录错误日志。
