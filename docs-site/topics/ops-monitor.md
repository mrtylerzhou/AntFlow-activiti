# 流程运维与监控实战

> 流程上线后，真正的挑战才刚刚开始：有人出差没审批、流程卡在某个节点不动了、需要紧急加人处理……AntFlow 的流程监控与运维模块就是为这些"意外"准备的瑞士军刀。

## 流程监控中心

进入 **流程管理 → 流程监控**，这里是所有运行中流程的"指挥舱"：

![流程监控列表](/images/topic-monitor-list.png)

### 列表信息一览

| 列 | 说明 |
|---|------|
| 流程类型 | 该实例所属的流程分类标识（如 `DSFZH_WMA`） |
| 流程名称 | 流程模板的显示名 |
| 版本编号 | 使用的流程定义版本号 |
| 流程描述 | 发起人填写的业务描述 |
| 状态 | 审批中 / 已完成 / 已终止 / 已退回 |
| 更新时间 | 最后一次状态变更时间 |
| 操作 | 查看 / 更多 |

### 查看流程详情

点击「查看」打开流程预览抽屉，可以看到：
- 当前流转到了哪个节点
- 每个节点的审批人是谁
- 历史审批记录
- 表单数据

## 运维操作菜单：9 种干预手段

点击「更多」按钮展开完整的运维操作菜单：

![更多运维菜单](/images/topic-monitor-more.png)

### 操作分类

```
┌─────────────────────────────────────────────┐
│              运维操作菜单                     │
├──────────┬──────────────────────────────────┤
│ 节点调整  │ 减签 · 加签 · 增加节点 · 删除节点   │
│ 流程控制  │ 推进流程 · 变更                    │
│ 终止类    │ 撤回 · 作废                       │
│ 通知类    │ 转发                              │
└──────────┴──────────────────────────────────┘
```

### 详细说明

#### 一、节点调整类

| 操作 | 说明 | 典型场景 |
|------|------|---------|
| **减签** | 从当前运行中的节点移除某人 | 审批人离职/调岗 |
| **加签** | 给当前或未来节点增加审批人 | 需要专家介入会商 |
| **增加节点** | 在当前节点后插入新节点 | 发现遗漏了审核环节 |
| **删除节点** | 删除运行中的某个节点 | 冗余环节需要跳过 |

#### 二、流程控制类

| 操作 | 说明 | 典型场景 |
|------|------|---------|
| **推进流程** | 强制跳过后续节点继续流转 | 流程卡住需要人工推进 |
| **变更** | 修改流程定义的某些属性 | 紧急调整审批规则 |

#### 三、终止类

| 操作 | 说明 | 典型场景 |
|------|------|---------|
| **撤回** | 将已提交的流程撤回到发起人 | 发起后发现错误需要取消 |
| **作废** | 直接终止流程（不可恢复） | 业务不再需要该审批 |

#### 四、通知类

| 操作 | 说明 | 典型场景 |
|------|------|---------|
| **转发** | 将流程抄送给相关人员查看 | 需要知会但不需审批的人 |

### 运维操作的加签页面

以「加签」为例，点击后进入专门的加签操作页面：

![加签运维页面](/images/topic-ops-addsign.png)

页面包含：
1. **流程基本信息**：类型、编号、描述、发起人、时间
2. **流程图预览**：可视化展示当前节点位置
3. **操作指引**：提示加/减/变更都是针对当前正在运行的节点

> ⚠️ **权限控制**：运维操作通常需要管理员角色。普通用户只能看到自己相关的流程。

## 全局高级设置

在流程设计向导的第 4 步「高级设置」中，可以为整个流程配置全局开关：

![向导高级设置](/images/topic-wizard-advanced.png)

### 可配置的全局开关

| 开关 | 默认值 | 效果 |
|------|--------|------|
| **允许撤回** | 关闭 | 开启后发起人可在「我的发起」中撤回已提交流程 |
| **允许作废** | 关闭 | 开启后发起人可作废已提交流程（终止态） |
| **允许转发** | 关闭 | 开启后所有相关人员可将流程转发给他人 |
| **审批人去重** | 不去重 | 同一人在多节点出现时的自动处理策略 |

### 审批人去重策略

| 策略 | 行为 |
|------|------|
| 不去重 | 同一人在每个节点都正常出现 |
| 前向去重 | 如果前面已经审批过，自动跳过 |
| 后向去重 | 如果后面还会遇到，合并处理 |

## 消息通知管理

进入 **流程运维 → 消息模板**：

![消息模板列表](/images/topic-msg-template.png)

消息模板用于：
- **审批到达通知**：提醒审批人有新的待办任务
- **超时催办通知**：任务超过设定时间未处理的提醒
- **流程结束通知**：告知发起人流程已完成
- **退回/驳回通知**：告知申请人需要修改

每种事件可以配置不同的消息渠道（站内信、邮件、企业微信等）和消息模板内容。

## 监控最佳实践

### 1. 定期检查卡住的流程

```sql
-- 查找超过 7 天未处理的待办任务
SELECT * FROM act_ru_task
WHERE CREATE_TIME_ < DATE_SUB(NOW(), INTERVAL 7 DAY);
```

### 2. 关注高频退回的流程

如果某类流程频繁被退回，通常意味着：
- 条件规则配置不合理
- 表单字段缺失校验
- 审批人培训不足

### 3. 合理使用委托而非转办

对于周期性离岗（如每周五下午），优先使用**委托功能**批量设置，而不是每次手动转办。
