# 多人审批与会签模式详解

> 当一个审批节点需要多人参与时，AntFlow 提供了 4 种会签模式 + 12 种审批人来源的灵活组合。本文从设计器配置到运行时行为，完整拆解多人审批机制。

## 为什么需要多人审批？

在实际业务中，一个节点往往不是"一个人说了算"。常见场景：

| 场景 | 示例 | 需要的模式 |
|------|------|-----------|
| 部门主管集体决策 | 人事、财务、法务共同审核 | **会签**（全部同意） |
| 任一负责人即可放行 | IT 部门任意运维人员处理 | **或签**（一人同意） |
| 按职级顺序审批 | 经理→总监→VP 逐级确认 | **顺序会签** |
| 投票表决 | 董事会按比例通过决议 | **仲裁签** |

## 审批人来源：12 种方式

在流程设计器的审批人节点配置面板中，你可以选择以下 12 种审批人来源：

![审批人配置面板](/images/topic-approver-panel.png)

### 来源分类一览

| 分类 | 来源类型 | 说明 |
|------|---------|------|
| **指定型** | 指定人员 / 指定角色 | 设计时固定写死 |
| **组织关系型** | 直属领导 / 层层审批 / 指定层级审批 / HRBP | 根据发起人的组织架构自动推导 |
| **发起人相关** | 发起人自己 / 发起人自选审批人 | 由发起人决定或自己审批 |
| **表单驱动** | 表单中选择 | 从表单字段动态读取 |
| **自定义扩展** | 自定义 / 上一节点审批人的 / 上一节点指定 | 通过 SPI 扩展或上下文传递 |

> 💡 **小贴士**：每种审批人来源背后对应一个 `NodePropertyXxxAdp` 适配器实现。新增审批人来源只需实现接口并注册，无需修改引擎核心代码。

## 会签模式：4 种策略

当同一节点配置了多个审批人时，会签模式决定了流程如何推进：

### 1. 会签（默认）

**规则：所有审批人都必须同意，不限审批顺序。**

![会签模式配置](/images/topic-approver-panel.png)

- 任何一人不同意 → 流程终止
- 所有人都同意 → 进入下一节点
- 适用场景：财务报销需出纳+会计双重确认

### 2. 或签

**规则：只需一名审批人同意（或拒绝）即可。**

- 第一个操作的人决定了该节点的结果
- 其他人看到任务自动消失
- 适用场景：IT 工单由任意值班人员处理

### 3. 顺序会签

**规则：所有审批人必须同意，且按指定顺序依次审批。**

- 前一人审批后，任务才流转到下一人
- 适用场景：跨部门逐级审批（经理→总监→VP）
- 顺序由前端传入的人员列表次序决定

### 4. 仲裁签

**规则：按通过比例完成审批。**

![仲裁签比例配置](/images/topic-signmode-arbitrate.png)

- 可设置通过比例阈值（如 50%、2/3）
- 达到比例即通过，未达到则拒绝
- 适用场景：董事会投票、专家评审委员会

## 运行时行为对比

假设节点 A 配置了审批人：张三、李四、王五

```
                    ┌─────────────────────────────┐
                    │        发起人               │
                    └──────────┬──────────────────┘
                               │
                    ┌──────────▼──────────────────┐
                    │   审批节点 A (3人)           │
                    │  张三 · 李四 · 王五          │
                    └──────────┬──────────────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
         ┌────▼────┐     ┌────▼────┐     ┌────▼────┐
         │  会签    │     │  或签    │     │ 顺序会签 │
         │ 全部同意 │     │ 一人即过 │     │ 依次审批 │
         └─────────┘     └─────────┘     └─────────┘
```

| 行为 | 会签 | 或签 | 顺序会签 | 仲裁签(50%) |
|------|------|------|----------|-------------|
| 张三同意后 | 李四、王五仍可见 | 任务结束 | 流转到李四 | 继续等待 |
| 李四拒绝后 | 流程终止 | （不会发生） | 流程终止 | 记录反对票 |
| 王五不操作 | 卡住等待 | — | 卡住等待 | 可能已通过 |

## 空审批人处理策略

当审批人来源解析结果为空（如角色下无成员、表单字段为空）时，有三种兜底策略：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| **不允许发起**（默认） | 报错提示，流程无法启动 | 严格管控场景 |
| **跳过** | 自动跳过此节点进入下一个 | 容错场景 |
| **转交给审核管理员** | 任务分配给系统管理员 | 兜底人工处理 |

## 如何在设计中配置

### 步骤一：添加审批人节点

在流程设计画布中点击 `+` 按钮，从节点菜单中选择「审批人」：

![添加节点菜单](/images/topic-designer-addnode.png)

### 步骤二：选择审批人来源

点击画布上的审批人节点，右侧弹出配置抽屉，在「审批人设置」tab 中：

1. 选择审批人类型（如"指定人员"）
2. 点击「添加/修改人员」按钮打开人员选择器
3. 勾选需要的审批人

![人员选择器](/images/topic-person-picker.png)

### 步骤三：设置会签模式

在同一面板下方，选择会签模式：

- 默认 **会签**（全员同意）
- 切换到 **或签** / **顺序会签** / **仲裁签**

### 步骤四：配置按钮权限（可选）

切换到「按钮权限设置」tab，控制该节点显示哪些操作按钮：

![按钮权限设置](/images/topic-node-buttons.png)

### 步骤五：通知与高级设置

- **通知设置**：配置审批到达/超时的消息模板
- **高级设置**：设置流程标签用于统计分析

## 与后端代码的映射

前端配置保存后，数据以 JSON 格式存储在 `t_bpmn_node.node_config_json` 字段的 `approverConf` 段中：

```json
{
  "approverConf": {
    "type": "personnel",           // 审批人类型
    "personnelConf": ["张三","李四"], // 指定人员列表
    "signMode": "countersign",     // 会签模式: countersign/orsign/sequential/arbitrate
    "arbitrateRate": null,         // 仲裁签比例（仅 arbitrate 模式）
    "emptyStrategy": "reject"      // 空审批人策略
  }
}
```

运行时，`BpmnNodeConfigJson.BpmnNodeApproverConfJson` 反序列化后交给对应的 `NodePropertyXxxAdp` 适配器处理。

## 常见问题

**Q: 可以混合使用不同审批人来源吗？**
A: 同一节点只能选择一种审批人来源，但可以通过"额外增加审批"追加其他来源的人员。

**Q: 会签模式下某人一直不审批怎么办？**
A: 可通过「催办」功能发送提醒消息，或在流程运维中使用「加签」/「变更处理人」介入。

**Q: 顺序会签的顺序能动态改变吗？**
A: 顺序由设计时确定的人员列表次序决定。如需动态排序，可使用「自定义」审批人来源配合 SPI 扩展。
